# Sentinel · 自动化安全评估系统

根据 `自动化安全评估系统.md` 实现的可运行第一版：FastAPI 后端、原生 HTML/CSS/JavaScript 中文前端、MySQL 持久化、线程任务调度、WebSocket 事件、源码静态分析与报告输出。无需 Node 构建前端。

## 1. 启动

在项目根目录使用 PowerShell，需 Python 3.12+、uv、MySQL 8.0+：

```powershell
uv sync --group dev
Copy-Item .env.example .env
notepad .env
uv run safety-assessment
```

**本机已创建 `.env` 并配置提供的数据库连接，无需覆盖它。** 数据库为 `127.0.0.1:3306/safety`；密码仅保存在被 `.gitignore` 忽略的本机 `.env`，文档不记录密码。系统读取 `.env`，操作系统环境变量优先。建议部署时换用只授权 `safety` 的专用数据库账户。

打开 <http://127.0.0.1:8000>，首次访问创建管理员（应用登录密码至少 8 位，与 MySQL 密码不同），然后登录。初始管理员仅能从本机建立。管理员可在“系统配置”页创建普通用户。

### 直接上传源码评估

登录后点击「创建评估项目」进入「上传源码评估」：

1. 选择或拖入 `.py` 文件、包含 Python 源码的 `.zip`，也可直接选择整个项目文件夹；支持多个文件及中文文件名，保留源码相对路径。
2. 点击「上传并开始评估」。项目名称自动生成，也可展开可选项填写名称与关注点。
3. 页面自动跳转实时监控；分析结束后在「漏洞与证据」「评估报告」查看结果或下载报告。

无需填写服务端源码目录、设置 `SAFETY_SOURCE_ROOTS` 或准备 Docker。默认只分析、不执行上传代码；模型未启用也能完成静态评估，已有模型配置会自动用于上传源码复核。也可切换「粘贴代码」，直接点击「开始评估」。原本的目录和 Git 接入收纳在「高级接入」中。

上传限制：一次最多 200 个 Python 文件（同时受管理员文件数量上限约束），单文件最多 1 MiB，原始上传及解压后的源码分别最多 20 MiB，ZIP 最多 10000 条目。非 Python 文件及依赖、隐藏目录自动忽略；危险路径、符号链接、重复或冲突路径、语法错误、非 UTF-8 源码会被明确拒绝，不创建半成品项目。源码和项目在同一事务中写入现有表；数据库表和字段无需变更。并发名额满时源码仍保存，可稍后在项目页启动。

数据库及现有 17 张业务表应提前存在；程序启动只检查表是否齐全，**不执行建表、删表或改字段语句**。`src/safety_assessment/schema.mysql.sql` 是结构参考，不会在启动时自动执行。若缺少表，程序列出缺失表并停止，不擅自修改数据库。当前本机 `safety` 连接及提交入库已验证。SQLite 仅用于无 MySQL 演示和自动化测试：

```powershell
$env:SAFETY_DB_BACKEND='sqlite'
uv run safety-assessment --port 8001
```

## 2. 完整演示及危险信号正反例

登录 → 左侧“正反案例” → “创建并启动危险案例” → 实时监控 → 漏洞与证据 → 攻击路径 → 评估报告下载。随后运行安全案例对照。

| 组别 | 触发危险信号（正例） | 不触发该信号（反例） |
| --- | --- | --- |
| SQL 注入 | 函数输入拼接到 SQL 字符串，再调用 `execute(query)` | `execute("... WHERE username = ?", (username,))` 参数化查询 |
| Shell 注入 | 输入拼接到字符串命令，并设置 `shell=True` | 校验 IP，使用 `subprocess.run(["ping", address], shell=False)` |

- `src/safety_assessment/examples/unsafe/app.py`：预期 **2 条**信号，SQL 高危与 Shell 严重风险。
- `src/safety_assessment/examples/safe/app.py`：预期 **0 条**上述信号。
- 分析器不会调用这些示例函数，不执行数据库查询或 ping。示例 SQL 的 `?` 占位符针对 SQLite 风格的被测源码，与评估平台自身使用 MySQL 无关。
- “不触发”只表示当前规则未命中，不是绝对安全保证。

命令行演示（先启动服务和初始化账户；输入应用登录密码）：

```powershell
uv run python scripts/demo.py --username admin
```

演示项目保留在工作台；脚本核对 2/0 条结果并打印报告地址。

## 3. 能力说明

- 项目创建、接入本机目录/公网 HTTPS Git、启动、停止、删除；五种项目状态与五阶段流水线。
- 创建 `inline` 项目后可在前端「提交代码」页粘贴 Python 代码；代码、静态结果、LLM 复核、分析状态全部写入 `safety` 数据库。
- 六类执行角色：通用协调、环境检查、代码分析、漏洞验证、报告整理、运维辅助。每个角色独立保存任务、阶段、时间、结果、错误。
- Python AST 规则：潜在外部输入到 SQL、Shell、动态 `eval/exec` 调用；支持基础赋值传播、部分分支合并、导入别名、忽略注释及字符串伪代码。
- 大语言模型采用 OpenAI Chat Completions 兼容协议，仅在管理员显式启用后调用；LLM 结果与静态规则结果分开保存并标记为 `needs_review`。
- 「提交代码」页列出已保存的提交、模型状态与错误，并可从数据库读回源码。源码、静态结果、模型结果分别保存在现有 `code_submissions`、`submission_analyses`、`llm_analyses` 表中；漏洞保存在 `vulnerabilities`。重新分析保留分析历史，但替换该提交的漏洞，不重复累加。
- `inline` 项目提交后可点击「启动评估」生成报告；模型失败不会阻止静态结果保存。提交代码需为有效 UTF-8 Python 源码，文件名以 `.py` 结尾，最大 1 MiB。
- 漏洞风险筛选、证据、触发条件、复现指引、核验方式、修复建议；候选路径及关联漏洞；Markdown/HTML 报告下载。
- 实时状态、角色消息、运行日志、后端进程 CPU/RSS、审计日志；WebSocket 及前端轮询回退。
- HttpOnly/SameSite 登录 Cookie、密码 PBKDF2 哈希、登录频率限制、管理员与项目所有者权限、同源写请求保护。
- 删除项目级联删除关联记录与 `runtime_logs/{id}`、`reports/{id}`、`workspace/{id}`，保留系统操作审计。
- 任务停止等待执行线程响应取消，不再推进后续阶段，保留已保存证据。服务重启将未完成任务标为失败。
- 当前每个项目只保存一次运行；重新评估请创建新项目，防止覆盖已有报告。

## 4. 隔离与接入

### 静态模式

独立环境编号、独立临时目录，只使用服务端 AST 解析源码；不安装目标依赖，不执行源码，也不接受任意 Shell 命令。**这是逻辑隔离演示，不是操作系统沙箱。**

### Docker 模式

```powershell
docker pull python:3.12-alpine
```

创建项目时选 Docker。服务创建独立容器、源码只读挂载 `/source`、禁网、只读根文件系统、非 root、丢弃 capabilities、限制 CPU/内存/PID，并执行固定环境探测命令。AST 分析仍由后端完成，不在容器中执行被测项目。容器在结束、失败或停止后销毁。**Docker Desktop 必须先启动；当前机器未运行 Docker daemon，真实容器链路尚未验收。** 不建议把宿主 Docker socket 暴露给不可信用户。

### 文件范围与仓库

默认只允许服务启动目录下的本地源码。额外目录通过 `SAFETY_SOURCE_ROOTS` 配置（Windows 用分号分隔），须确保服务账户只拥有必要读取权限。跳过依赖目录、凭据目录、符号链接、超限文件，仅分析 UTF-8 Python 文件。默认最多 2000 个 Python 文件、单文件 1 MiB、最多 20000 个遍历文件条目；命中遍历/文件数量上限会使任务失败而非宣称完整扫描。

Git 接入限制公网 HTTPS、禁凭据 URL、禁重定向、禁子模块、禁 hooks、浅克隆、超时限制。源码拉取发生在隔离分析前的服务端接入阶段。公网 DNS 校验不是完整 SSRF 防护；生产环境必须额外使用网络出口白名单/代理抵御 DNS 重绑定，并限制克隆磁盘配额。

## 5. 配置与运行边界

### 时间格式

所有业务时间字段（创建、更新、开始、结束、资源记录）、实时事件时间和新写入的运行日志统一使用北京时间 `YYYY/MM/DD/HH.mm`，例如 `2026/10/23/10.11`。前端直接显示同样格式。精度为分钟，同分钟记录以 ID 区分顺序；不会把所有记录改成示例中的同一个时间。登录会话的 `expires_at` 保留数值时间戳，保证 8 小时登录有效期判断不受影响。

历史时间迁移工具为 `scripts/migrate_timestamps.py`，默认只检查；停止服务后加 `--apply` 执行，先备份到 `data/backups/timestamps-before-*.json`，再在单一事务中将原 UTC 时间换算为北京时间并转换格式，保留空值，不改表结构及其他字段。重复执行不重复偏移时区。备份包含被转换的原始秒和毫秒，可在停止服务、数据未进一步变动时用 `--restore 备份路径` 恢复。历史文件日志作为原始运行档案保留，不改写业务源码、模型响应或既有报告正文里的日期。

`.env.example` 列出 MySQL 和可选 LLM 参数；`SAFETY_DATA_DIR` 控制文件目录（默认 `data/`）。`SAFETY_SOURCE_ROOTS` 控制源码范围。系统配置页面可维护超时、并发、保留天数、Docker 镜像、Git 开关及文件限额。

### LLM 配置位置与启用

已有完整的模型请求链路，不是仅有 `body.base_url` 占位代码；`body.base_url` 指管理员配置请求中的 Base URL 字段。默认关闭且未提供密钥时不会调用模型。

两种配置方式任选其一：

1. 使用管理员账户登录，打开左侧「系统配置」（`http://127.0.0.1:8000/#config`），在「大语言模型配置」填写 Base URL、API Key、模型名称，选择启用并保存。普通用户不显示此页。
2. 编辑本机 `.env` 的 `SAFETY_LLM_ENABLED`、`SAFETY_LLM_BASE_URL`、`SAFETY_LLM_API_KEY`、`SAFETY_LLM_MODEL`，然后重启服务。可额外设置 `SAFETY_LLM_TIMEOUT_SECONDS` 和 `SAFETY_LLM_MAX_CODE_CHARS`。密钥须由模型服务商提供，本项目不生成密钥。

**优先级：操作系统环境变量 > `.env` > 页面保存在数据库中的配置。** 空白环境项使用数据库配置；非空环境项覆盖页面，页面会列出覆盖字段。将 `SAFETY_LLM_ENABLED=true` 且填入密钥才会启用 `.env` 配置的模型；仅填写密钥不会自动启用。API Key 不从接口返回；环境变量密钥不会被复制进数据库，页面填写的密钥存于现有 `system_config` 表，须限制数据库访问及备份权限。

Base URL 填服务商提供的兼容接口根地址，通常以 `/v1` 结尾；程序追加 `/chat/completions`，也接受完整的 `/chat/completions` 地址。服务必须支持 Chat Completions 及 JSON 对象输出。`GET /api/system/llm/health` 只显示配置状态，不声称连通。页面「测试已保存的连接」会实际发送一段无业务数据的代码，验证密钥、模型名称及 JSON 返回格式，可能产生少量调用费用。**测试成功后再提交业务代码；开启模型意味着送审源码会发往所配置的服务。**

当前对上传文件、文件夹、ZIP、直接粘贴及「提交代码」路径进行模型复核，本机目录和 Git 仓库流水线仍只运行 AST 规则。源码超过送审字符数时只发送前段，并在模型摘要明确标注，不代表全文已审查。

Navicat 的 `.ncx` 文件是连接配置，不是 SQL 结构或数据导出。本次读取了本机数据库实际结构；没有根据 `.ncx` 推断或重建任何表。

**重要边界：**

- `static_confirmed` 是第二次静态规则核验，不是动态攻击验证。不运行 exploit、不自动证明入口可控性、没有完整跨文件/跨函数分析。函数参数被视为潜在外部输入，存在误报与漏报。
- 候选攻击路径目前为单漏洞数据流，不拼凑未经证明的跨漏洞攻击链。
- 资源为整个后端进程的 CPU/RSS，不是项目或容器独占消耗；token 字段当前未统计，0 不表示没有模型调用。
- `retention_days` 当前只保存保留策略，不运行自动清理；在项目页手动删除数据。
- 仅单服务进程运行，不使用 `uvicorn --workers` 多进程；否则内存调度锁与实时事件不会跨进程同步。生产应迁移到持久任务队列、独立沙箱执行器及集中消息系统。
- 不支持的语言、跳过的文件、规则未覆盖的数据流，不构成安全保证。报告必须由安全人员复核。
- 生产部署需 HTTPS、专用数据库账户、受限网络出口、数据备份与日志脱敏。不要开放到公网后让任意用户接入宿主文件系统。

## 6. 测试

```powershell
uv run pytest -q
```

可选浏览器冒烟检查（本机 Chrome/Edge，临时 SQLite，不改 MySQL）：`uv run python scripts/browser_smoke.py`。覆盖管理员 LLM 配置入口、连接测试按钮、代码提交/读回和移动端页面。

默认用独立临时 SQLite 数据库，不修改 MySQL。真实 MySQL 集成测试需显式开启（仅在没有其他评估任务运行时执行）：

```powershell
$env:SAFETY_TEST_MYSQL='1'
uv run pytest tests/test_mysql.py -q
Remove-Item Env:SAFETY_TEST_MYSQL
```

集成测试创建临时应用账户、正反项目与提交代码，验证中文源码原样保存、模型成功/失败状态、重复分析和报告生成；模型 HTTP 响应由测试模拟，不向外发送源码。完成后删除临时业务记录，保留操作审计，不清空已有业务数据。测试前后比较表清单及 `SHOW CREATE TABLE`（忽略自增计数），确认结构不变。

接口细节见 `docs/API.md`；交互式接口文档：<http://127.0.0.1:8000/docs>。
